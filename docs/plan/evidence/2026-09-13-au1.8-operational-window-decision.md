# AU1.8 operational-window decision — 2026-09-13

The scoped, paused AU1.8 canary uses a finite **2,400-second (40-minute)**
operational window. It replaces the harness's former 600-second internal
limit; that value was not a normative or security credential TTL.

The observed attempt started at 15:59:55 and reached the armed ready/bindings
state at 16:08:13: **498 seconds** before a new credential-ticket secret could
be written. The 600-second harness ceiling then made the required rotation,
proof, and disarm sequence unable to complete and produced RED before the new
secret mutation.

The 40-minute allowance is bounded to this paused, tenant-scoped canary arm.
Its temporary-key exposure remains constrained by the existing exact-binding,
tenant, admission-pause, fleet/quiescence, secret, digest, and final-disarm
checks. Before the first new `FABRIC_CRED_TICKET_SECRET` put, the harness now
requires at least **900 seconds** remaining. A slow arm fails closed before
the permanent credential changes; the existing exit rollback restores the old
signer and performs cleanup even after the primary window has expired.

Evidence records the actual elapsed time and takes `maximum_seconds` from the
same named script constant, preventing a source/evidence budget drift.
