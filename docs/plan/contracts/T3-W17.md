## Configuration and control route

- The independent switches are `AUTOSCALER_INTAKE_PAUSED` and
  `AUTOSCALER_REDRIVE_PAUSED`.
- Unset and exact `"0"` mean normal operation; exact `"1"` means paused.
  Every other present value, including blank, whitespace, case variants,
  booleans, and numeric lookalikes, is invalid and fails closed independently:
  intake is paused or re-drive is suppressed, respectively. Invalid config
  emits one deduplicated `CONTAINMENT_CONFIG_INVALID` signal. The singleton DO
  deduplicates on `(switch_name, sha256(raw_value))` at
  `containment:v1:invalid:<switch_name>:<raw_value_sha256>` and atomically writes
  a pending outbox record carrying the same stable `signal_id`. `metrics.ts`
  registers `containment_config_invalid` and adds `MetricsDO.bumpOnce(signal_id,
  name)`, which atomically stores the signal id and increments the counter.
  Delivery is attempted immediately after commit and by every existing
  scheduled tick; no new cron is added. Both paths retry the same outbox record
  until that idempotent call is acknowledged, then mark it delivered in the
  containment authority. Thus a crash or cross-DO failure loses or increments
  no signal twice. Failure to commit the containment record returns 503; a
  metrics-delivery failure leaves it pending and preserves the independently
  fail-closed switch result.
- `POST /internal/v1/containment/drain` uses only `CONTAINMENT_ADMIN_KEY` via
  `X-Corelink-Internal-Auth`. Missing configured key returns 404; mismatch
  returns 401. The route accepts an empty body only; a nonempty body returns
  400. A valid request transactionally sets `drain_requested` to
  `backlog_count > 0` and returns 200 with exact JSON `{schema_version:1,
  drain_requested, intake_paused, backlog_count, drain_cursor}`. Thus an empty
  backlog returns `drain_requested:false`; a nonempty backlog records `true`.
  While intake is paused a recorded request performs no continuation. Repeated
  requests are idempotent. A later acknowledgement clears `drain_requested`
  only in the transaction that reduces `backlog_count` to zero; the route
  cannot alter either switch.

## Durable authority

- Add a SQLite-backed singleton `ContainmentDO`, binding `CONTAINMENT`, addressed
  with `idFromName("global")`, and Wrangler migration `v7`.
- Do not use KV read/modify/write as sequencing, lease, or cursor authority.
- Storage keys are:
  - `containment:v1:meta`
  - `containment:v1:event:<event_id>`
  - `containment:v1:pause:<pause_seq padded to 20 decimal digits>`
- The exact meta shape is:

  ```ts
  {
    schema_version: 1;
    next_pause_seq: number; // starts at 1; never reused or decreased
    drain_cursor: number;   // last acknowledged sequence; starts at 0
    backlog_count: number;  // exact unacknowledged pause-record count
    lease_epoch: number;    // starts at 0; increments on acquire/reclaim
    lease: { owner: string; epoch: number; expires_ms: number } | null;
    drain_requested: boolean;
  }
  ```

- Each event stores `schema_version`, `event_id`, `pause_seq`,
  `received_at_ms`, `body_sha256`, the verified raw payload, normalized
  `job_id/repo/installation_id/labels`, stable `effect_id`, state
  `QUEUED | CLAIMED | EFFECT_COMMITTED`, and nullable
  `claim:{owner, lease_epoch}` plus nullable one-shot
  `effect_permit:{permit_id,issued_to_owner,issued_to_epoch}`. The pause record is exactly
  `{schema_version:1,event_id,pause_seq}`; it contains no second mutable state.
- A nonempty `X-GitHub-Delivery`, after trimming surrounding ASCII whitespace,
  is `event_id`; an empty/whitespace-only header is absent. The fallback is
  `sha256("containment:v1\n" + decimal(workflow_job.id) + "\n" + action +
  "\n" + sha256(raw_body_bytes))`. Malformed JSON after a valid HMAC returns
  400 with no durable write. With a delivery header, reuse against a different
  `body_sha256` is a typed 409 conflict and allocates no sequence. Without the
  header, different raw bytes necessarily produce different fallback ids.
- One DO transaction deduplicates, allocates `next_pause_seq`, writes event and
  ordered pause record, and advances the sequence. The Worker returns 202 only
  after commit. Any append/read authority failure returns 503 and causes zero
  claim, JIT, slot, lease, start, destroy, or success-metric side effects.

## Intake placement

1. Verify webhook configuration, HMAC, event type, and delivery/job identity.
2. Parse the payload and classify managed labels using side-effect-free code.
3. Route `workflow_job:completed` through the existing cleanup path regardless
   of containment: placement clear, PAT revoke, slot release, usage ledger,
   billing, teardown, credential wipe, and completion dedup continue.
4. For managed `queued`, consult the intake switch and durable backlog before
   entitlement, installation allowlist, rate limit, spawn claim, mint, slot,
   JIT, lease, or start.
5. Paused, invalid, or nonempty-backlog intake appends durably and returns 202.
   A fresh event never bypasses an older draining backlog.
6. Disarmed intake with an empty backlog continues through the existing queued
   path without semantic changes.

## Ordered resume

- A drain may be requested by the authenticated route, the existing scheduled
  tick, or a verified webhook that observes disarmed intake. No new cron exists.
- `DRAIN_LEASE_TTL_MS = 120_000`; renew when remaining TTL is at most 30,000 ms.
  Lease acquire/renew/reclaim is transactional and uses a random owner token.
  Acquire or expired-lease reclaim increments `lease_epoch`; renew preserves
  it. Every claim/commit/ack operation supplies `(owner, lease_epoch)` and its
  transaction rejects a stale token. Exactly one owner may claim, renew,
  commit, or acknowledge the head.
- Drain strictly increasing `pause_seq`, one head at a time. A stuck head blocks
  later events and is never skipped. Fresh arrivals append after the durable
  high-water mark.
- `claimNext` transactionally moves `QUEUED -> CLAIMED` and persists stable
  `effect_id = containment:v1:<event_id>` plus the current claim token. If the
  head is already `CLAIMED` when an expired lease is reclaimed, the new owner
  replaces only its claim token; it never allocates a new sequence or skips the
  head. Before the extracted queued continuation may cross its first
  irreversible-effect seam, `beginEffect` transactionally creates the one-shot
  permit for the current fenced token. That permit is never reassigned. Only
  its issued owner may enter the continuation, with containment bypass only for
  that head.
- Reclaim before `beginEffect` may replay and acquire the sole permit. Reclaim
  after a permit exists must never call mint, JIT, slot, lease, start, destroy,
  or any other continuation effect again. It performs recovery-only inspection
  of the existing `spawn:<jobId>` claim, attempt, placement, lease, and result
  records using the stable `effect_id`; a proven committed result may advance,
  while absent or uncertain proof blocks the head fail-closed. A time boundary
  alone never reissues a permit. An old permit holder may finish, but the new
  owner cannot race it through a second effect path.
- Existing `spawn:<jobId>` claim, orphan/placement records, and completion
  cleanup remain idempotency layers. After its durable continuation result,
  `markEffectCommitted` moves `CLAIMED -> EFFECT_COMMITTED`.
- `markEffectCommitted` and acknowledgement require the current fenced claim
  token; a late former owner is a typed no-op. A reclaiming owner may instead
  call `recoverEffectCommitted(effect_id, current_claim_token, proof_digest)`.
  That operation executes no continuation effect and atomically changes
  `CLAIMED -> EFFECT_COMMITTED` only when the existing spawn claim, attempt,
  placement, lease, and terminal-result records are all bound to the same
  `effect_id` and hash to `proof_digest`; missing, divergent, or nonterminal
  proof is a typed no-op and leaves the head blocked. Only a transaction
  observing `EFFECT_COMMITTED` may remove the pause/event record, decrement
  `backlog_count`, and advance `drain_cursor`. Crashes before claim, after claim, after
  continuation side effects, and before cursor acknowledgement recover the
  same event/effect without bypassing or creating a second eligibility. The
  "after claim" replay fixture crashes before `beginEffect`; an issued-but-
  unresolved permit is deliberately fail-closed rather than replayed.
- A second drain after success is empty.

## Re-drive containment

- When `AUTOSCALER_REDRIVE_PAUSED` is exact `"1"` or invalid,
  `redriveOrphanedJobs` returns before GitHub listing, claim release, claim,
  JIT, mint, slot, lease, drive, start, or destroy.
- Under the same condition, `retryOrphanedSpawns` returns before KV listing,
  attempt mutation, verification, claim, drive, start, or destroy.
- Re-drive-only containment leaves verified fresh webhook intake on its normal
  continuation. Intake-only containment leaves pre-existing re-drives on their
  normal continuation. Both switches together suppress both surfaces.
