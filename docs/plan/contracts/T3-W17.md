## Configuration and control route

- The independent switches are `AUTOSCALER_INTAKE_PAUSED` and
  `AUTOSCALER_REDRIVE_PAUSED`.
- Unset and exact `"0"` mean normal operation; exact `"1"` means paused.
  Every other present value, including blank, whitespace, case variants,
  booleans, and numeric lookalikes, is invalid and fails closed independently:
  intake is paused or re-drive is suppressed, respectively. Invalid config
  emits one deduplicated `CONTAINMENT_CONFIG_INVALID` signal.
- `POST /internal/v1/containment/drain` uses only `CONTAINMENT_ADMIN_KEY` via
  `X-Corelink-Internal-Auth`. Missing configured key returns 404; mismatch
  returns 401; a valid request idempotently requests a drain and returns its
  status as 200. The route cannot alter either switch.

## Durable authority

- Add a SQLite-backed singleton `ContainmentDO`, binding `CONTAINMENT`, addressed
  with `idFromName("global")`, and Wrangler migration `v7`.
- Do not use KV read/modify/write as sequencing, lease, or cursor authority.
- Storage keys are:
  - `containment:v1:meta`
  - `containment:v1:event:<event_id>`
  - `containment:v1:pause:<pause_seq padded to 20 decimal digits>`
- The exact meta shape is:

  ```ts
  {
    schema_version: 1;
    next_pause_seq: number; // starts at 1; never reused or decreased
    drain_cursor: number;   // last acknowledged sequence; starts at 0
    lease: { owner: string; expires_ms: number } | null;
    drain_requested: boolean;
  }
  ```

- Each event stores `schema_version`, `event_id`, `pause_seq`,
  `received_at_ms`, the verified raw payload, normalized
  `job_id/repo/installation_id/labels`, stable `effect_id`, and state
  `QUEUED | CLAIMED | EFFECT_COMMITTED`.
- `event_id` is `X-GitHub-Delivery`. If absent, it is the deterministic tuple
  `workflow_job.id + action + SHA-256(raw body)`. Reuse with different bytes is
  a typed conflict and allocates no second sequence.
- One DO transaction deduplicates, allocates `next_pause_seq`, writes event and
  ordered pause record, and advances the sequence. The Worker returns 202 only
  after commit. Any append/read authority failure returns 503 and causes zero
  claim, JIT, slot, lease, start, destroy, or success-metric side effects.

## Intake placement

1. Verify webhook configuration, HMAC, event type, and delivery/job identity.
2. Parse the payload and classify managed labels using side-effect-free code.
3. Route `workflow_job:completed` through the existing cleanup path regardless
   of containment: placement clear, PAT revoke, slot release, usage ledger,
   billing, teardown, credential wipe, and completion dedup continue.
4. For managed `queued`, consult the intake switch and durable backlog before
   entitlement, installation allowlist, rate limit, spawn claim, mint, slot,
   JIT, lease, or start.
5. Paused, invalid, or nonempty-backlog intake appends durably and returns 202.
   A fresh event never bypasses an older draining backlog.
6. Disarmed intake with an empty backlog continues through the existing queued
   path without semantic changes.

## Ordered resume

- A drain may be requested by the authenticated route, the existing scheduled
  tick, or a verified webhook that observes disarmed intake. No new cron exists.
- `DRAIN_LEASE_TTL_MS = 120_000`; renew when remaining TTL is at most 30,000 ms.
  Lease acquire/renew/reclaim is transactional and uses a random owner token.
  Exactly one owner may claim, renew, commit, or acknowledge the head.
- Drain strictly increasing `pause_seq`, one head at a time. A stuck head blocks
  later events and is never skipped. Fresh arrivals append after the durable
  high-water mark.
- `claimNext` transactionally moves `QUEUED -> CLAIMED` and persists stable
  `effect_id = containment:v1:<event_id>`. The extracted queued continuation is
  invoked internally with containment bypass only for that claimed head.
- Existing `spawn:<jobId>` claim, orphan/placement records, and completion
  cleanup remain idempotency layers. After its durable continuation result,
  `markEffectCommitted` moves `CLAIMED -> EFFECT_COMMITTED`.
- Only a transaction observing `EFFECT_COMMITTED` may remove the pause/event
  record and advance `drain_cursor`. Crashes before claim, after claim, after
  continuation side effects, and before cursor acknowledgement replay the same
  event/effect without bypassing or creating a second eligibility.
- A second drain after success is empty.

## Re-drive containment

- When `AUTOSCALER_REDRIVE_PAUSED` is exact `"1"` or invalid,
  `redriveOrphanedJobs` returns before GitHub listing, claim release, claim,
  JIT, mint, slot, lease, drive, start, or destroy.
- Under the same condition, `retryOrphanedSpawns` returns before KV listing,
  attempt mutation, verification, claim, drive, start, or destroy.
- Re-drive-only containment leaves verified fresh webhook intake on its normal
  continuation. Intake-only containment leaves pre-existing re-drives on their
  normal continuation. Both switches together suppress both surfaces.
