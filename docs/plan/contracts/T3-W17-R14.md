## Frozen data contracts

### Canonical identity

`normalizeRedriveIdentity(repo, job_id)` is the only identity normalizer and runs
before every key, map, reservation, event, claim, effect, or credential lookup.
It trims ASCII surrounding whitespace, validates exactly one GitHub
`owner/name` pair, and canonicalizes both owner and repository to lowercase for
containment identity. Allowlist and installation-map comparisons use the same
canonical form; the original display spelling is not a second identity. A
malformed or ambiguous alias is a typed fail-closed refusal.

`job_id` is canonical decimal text: `[1-9][0-9]*`, with
`1 <= BigInt(job_id) <= 9007199254740991`. Leading zeroes, signs, whitespace,
fractions, exponent notation, negative values, unsafe integers, and numeric
round-trips are refused. The canonical pair is the only input to reservation,
event, effect, spawn-claim, and evidence keys.

### Schema/version boundary

Every durable containment record, API response, effect permit/binding, metric
outbox signal, and deterministic evidence record carries `schema_version: 1`.
Readers reject an unsupported or missing version before any mutation; writers
never silently upgrade, downgrade, or interpret an unknown version. The focused
tests enumerate every record kind and include an unsupported-version refusal.

The canonical event shape remains:

```ts
{
  schema_version: 1;
  event_id: string;
  pause_seq: number;
  received_at_ms: number;
  body_sha256: string;
  raw_payload: string;
  repo: string;             // canonical owner/name
  job_id: string;           // canonical decimal
  installation_id: number;
  labels: string[];
  effect_id: string;
  state: "QUEUED" | "CLAIMED" | "EFFECT_COMMITTED";
  claim: { owner: string; lease_epoch: number } | null;
  effect_permit: { permit_id: string; issued_to_owner: string;
                   issued_to_epoch: number } | null;
}
```

Pause, reservation, permit, binding, invalid-config outbox, and metric signal
records use the same version gate. The effect id is stable for one canonical
`repo/job/effect` tuple and is never used to authorize a second effect.

### Expired HELD and reservation fencing

The exact reservation key is
`containment:v1:reservation:<canonical-repo>/<canonical-job-id>`. A `HELD`
reservation with `expires_ms > now` returns `authority-busy` and writes no
event. A `HELD` reservation with `expires_ms <= now` is reclaimed atomically in
the deciding Durable Object transaction, increments its epoch, and receives a
new transaction-generated owner/token. Equality at the boundary is expired.
Only `HELD` may be reclaimed. `EFFECT_ELIGIBLE` and `COMPLETED` never expire,
reopen, or receive a new permit. Every transition supplies and checks the full
`(repo, job_id, owner, token, epoch, path, effect_id)` tuple; a stale owner is a
typed no-op touching no KV or effect state.

### Repo-scoped containment binding

`containmentEffectJobKey` and its binding record must include the canonical repo
and canonical job id. The binding schema is:

```ts
{
  schema_version: 1;
  repo: string;
  job_id: string;
  event_id: string;
  effect_id: string;
  permit_id: string;
  reservation_epoch: number;
  issued_to_owner: string;
}
```

Two repositories using the same numeric job id must never share a claim,
binding, completion latch, or effect. A job-only `containment:v1:job:<id>` key is
forbidden for this path. Broader legacy per-job keys are recorded separately in
the R14 ledger and are outside this repair contract.

### Bounded event index

`containedEventExists` must use a bounded, transactionally maintained index,
not a prefix scan of all event records. The index key is
`containment:v1:repo-job-index:<canonical-repo>/<canonical-job-id>` and its
schema is:

```ts
{
  schema_version: 1;
  repo: string;
  job_id: string;
  active_event_ids: string[];
  active_count: number;
  updated_at_ms: number;
}
```

The implementation declares and enforces a finite maximum index size. At the
limit, the transaction fails closed with a retryable typed error; it does not
scan, allocate unbounded memory, append an event, or admit an effect. Append,
claim/acknowledge, and terminal cleanup update the index in the same singleton
DO transaction, and tests prove no orphan index entry and no event/index
divergence. `CONTAINMENT.idFromName("global")` remains the sole authority; the
Wrangler migration is additive and no per-job/per-repo DO is introduced.

### Pre-effect spawn-owner protocol

Before `beginEffect` or `beginReservedEffect`, the singleton `ContainmentDO`
records a pre-effect spawn owner for the exact canonical repo/job/event/effect
tuple and the drain lease epoch. The record is transactionally bound to the
reservation but carries no permit and authorizes no external effect. The live
producer and both redrive functions use the same protocol; a caller may not
invent a boolean claim result or bypass the DO ledger.

The KV-facing claim boundary returns one of these typed results:

```text
acquired        = exact prepared owner atomically acquired the claim
owned           = exact same prepared owner already owns the claim, idempotently
busy            = another current owner holds the claim
legacy_unknown  = a legacy/job-only claim exists without the exact repo binding
unavailable     = claim store is unreadable or the operation is indeterminate
```

`acquired` and an exact matching `owned` result are the only results eligible
to proceed to `beginEffect`/`beginReservedEffect`; the DO verifies the owner,
tuple, epoch, and absence of a permit/effect before issuing that one-shot
transition. `busy`, `legacy_unknown`, and `unavailable` leave the drain head
unacknowledged and the redrive reservation `HELD`, issue no permit, and perform
zero orphan-attempt, release, JIT, mint, lease, start, destroy, or effect
mutations. An indeterminate/false result is never treated as success and never
spins a retry loop. Only the exact pre-effect owner, with no permit and no
effect started, may abort its prepared claim; once `EFFECT_ELIGIBLE` or any
external effect exists, the record is never reset or abandoned by time.

The pre-effect ledger is versioned and repo-scoped:

```ts
{
  schema_version: 1;
  repo: string;
  job_id: string;
  event_id: string;
  effect_id: string;
  reservation_epoch: number;
  drain_owner: string;
  drain_lease_epoch: number;
  spawn_owner: string;
  state: "PREPARED" | "CLAIM_ACQUIRED" | "EFFECT_ELIGIBLE";
}
```

## Frozen behavior and invariants

1. **Claim-false liveness.** In `runContainmentDrain`, a false or typed
   `busy`/`legacy_unknown`/`unavailable` claim result is a blocked/unknown
   outcome. The event remains the head, the redrive reservation remains `HELD`,
   no permit is issued, no second claim is attempted, and the worker does not
   spin. A false claim can never be reported as successful drain/redrive.
2. **One-shot effect.** `beginReservedEffect` is issued only after the
   singleton pre-effect owner ledger records an exact `acquired`/`owned` claim.
   A stale tuple, missing permit, failed index transaction, or non-acquired
   claim has zero spawn/JIT/mint/lease/start/destroy side effects. Once
   `EFFECT_ELIGIBLE` or a started effect exists, no reset or abandonment path
   may reopen it.
3. **Ordered head.** Drain consumes strictly increasing pause sequence, one
   head at a time. A blocked head remains durable and blocks later heads; an
   event is ACKed only after its effect and completion evidence are committed.
4. **Singleton authority.** All sequence, reservation, lease, cursor, state,
   index, and completion transitions occur transactionally in the global DO.
   KV is an idempotency cache only.
5. **Webhook separation.** A normal webhook with an empty backlog follows its
   existing path and neither consults nor reserves a redrive reservation. A
   containment append is the only route that performs the reservation check.
6. **Invalid-config distinction.** Each `(switch_name, raw_value_sha256)` gets
   one durable signal/outbox id. Distinct raw values and distinct switches get
   distinct signals; retries and scheduled delivery call `bumpOnce` once per
   signal after the containment record commits.
7. **Population.** A deterministic route fixture creates 100 distinct paused
   events, contiguous sequence records, and exactly 100 successful effects.
   Every effect is uniquely bound to one canonical event; no duplicate mint,
   JIT, claim, lease, start, ACK, or effect commit occurs.
8. **Idle status.** `runnerActivityVerdict` classifies idle, offline, and HTTP
   404 as no-renew; unknown remains renewable. The previous “keepalive burns
   idle capacity” claim is REFUTED and is not reintroduced by this contract.

## Evidence provenance and indexing

The deterministic evidence artifact must be generated only after focused tests
finish and must carry an explicit, externally supplied input SHA. Its version-1
index record is:

```text
EVIDENCE_INDEX_V1=(schema_version,artifact_id,review_input_sha,source_commit_sha,
contract_sha256,source_tree_sha256,test_tree_sha256,focused_test_counts,
sequence_id,sequence_position,previous_digest,current_digest,status,created_at)
```

`current_digest` covers the canonical preceding fields and the byte-preserved
focused test output. The index is append-only, positions are contiguous from
zero, `previous_digest` must equal the prior record, and an artifact cannot
reference its own future commit SHA. The record names exact test files, test
counts, source/contract tree digests, and `live: false`; absent, partial,
self-referential, or moving-HEAD provenance is RED. Phase-B gate repair owns
the independent plan-integrity completion record; this contract does not claim
that gate is fixed.
