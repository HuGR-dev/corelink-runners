## Frozen data contracts

### Canonical identity

`normalizeRedriveIdentity(repo, job_id)` is the only normalizer before any key, map, reservation,
event, claim, effect, or credential lookup. It trims ASCII surrounding whitespace, validates one
GitHub `owner/name`, lowercases both for containment identity, and uses that form for allowlists/maps;
malformed or ambiguous aliases are typed fail-closed refusals.

`job_id` is canonical decimal `[1-9][0-9]*`, with `1 <= BigInt(job_id) <= 9007199254740991`.
Leading zeroes, signs, whitespace, fractions, exponents, negatives, unsafe integers, and numeric
round-trips are refused; only the canonical pair enters reservation, event, effect, claim, and evidence keys.

Webhook `workflow_job.id` may be a JSON safe integer or a decimal string; both
normalize to the same string. A non-integer/unsafe number, noncanonical string,
null, boolean, array, or object is a 400 typed refusal before a write. String
IDs trim only surrounding ASCII space/tab/CR/LF; an all-whitespace value is
absent and any internal or non-ASCII whitespace is invalid. Repository and
delivery-header trimming follows the same rule. `installation_id` is stored and
keyed as canonical decimal **string** (same bound and refusal rules), never as
a number. Containment-only JSON responses have exactly `{schema_version:1,...}`
with no unversioned or live-status fields.

For webhook identity, a nonempty trimmed `X-GitHub-Delivery` is the event id;
blank/ASCII-whitespace-only is absent. Without it, the fallback is
`sha256("containment:v1\n"+repo+"\n"+job+"\n"+action+"\n"+sha256(raw_body_bytes))`.
Delivery reuse with a different body hash is a typed 409 with no new sequence;
malformed JSON after valid HMAC is a 400 with no durable write.

### Schema/version boundary

Every durable record, API response, effect permit/binding, metric outbox, and evidence record carries
`schema_version: 1`; missing/unsupported versions are rejected before mutation, never upgraded or
interpreted, and are enumerated by focused refusal tests.

The canonical event shape remains:

```ts
{
  schema_version: 1;
  event_id: string;
  pause_seq: number;
  received_at_ms: number;
  body_sha256: string;
  raw_payload: string;
  repo: string;             // canonical owner/name
  job_id: string;           // canonical decimal
  installation_id: string;  // canonical decimal installation id
  labels: string[];
  effect_id: string;
  state: "QUEUED" | "CLAIMED" | "EFFECT_COMMITTED";
  claim: { owner: string; lease_epoch: number } | null;
  effect_permit: { permit_id: string; issued_to_owner: string;
                   issued_to_epoch: number } | null;
}
```

Pause, reservation, permit, binding, outbox, and metric records use the same gate. Exact derivations:
`redriveEffectId(repo,job)=containment:v1:redrive:<repo>/<job>` and
`intakeEffectId(repo,job,event)=containment:v1:intake:<sha256("containment:v1\nintake\n"+repo+"\n"+job+"\n"+event)>`; SHA-256 is lowercase hex over UTF-8 bytes and never authorizes a second effect.

### Expired HELD and reservation fencing

The exact reservation key is
`containment:v1:reservation:<canonical-repo>/<canonical-job-id>`. A `HELD`
reservation with `expires_ms > now` returns `authority-busy` and writes no
event. A `HELD` reservation with `expires_ms <= now` is reclaimed atomically in
the deciding Durable Object transaction, increments its epoch, and receives a
new transaction-generated owner/token. Equality at the boundary is expired.
Only `HELD` may be reclaimed. `EFFECT_ELIGIBLE` and `COMPLETED` never expire,
reopen, or receive a new permit. Every transition supplies and checks the full
`(repo, job_id, owner, token, epoch, path, effect_id)` tuple; a stale owner is a
typed no-op touching no KV or effect state.

### Repo-scoped containment binding

`containmentEffectJobKey` and its binding record must include the canonical repo
and canonical job id. The binding schema is:

```ts
{
  schema_version: 1;
  repo: string;
  job_id: string;
  event_id: string;
  effect_id: string;
  permit_id: string;
  reservation_epoch: number;
  issued_to_owner: string;
}
```

Two repositories using the same numeric job id must never share a claim,
binding, completion latch, or effect. A job-only `containment:v1:job:<id>` key is
forbidden for this path. Broader legacy per-job keys are recorded separately in
the R14 ledger and are outside this repair contract.

### Bounded event index

`containedEventExists` must use a bounded, transactionally maintained index,
not a prefix scan of all event records. The index key is
`containment:v1:repo-job-index:<canonical-repo>/<canonical-job-id>` and its
schema is:

```ts
{
  schema_version: 1;
  repo: string;
  job_id: string;
  active_event_ids: string[];
  active_count: number;
  updated_at_ms: number;
}
```

`MAX_ACTIVE_INDEX_EVENTS` is fixed at **256** (at least 100). At its limit the transaction fails
closed without scan/allocation/append/admission; append, claim/ack, and cleanup update the index in
the same DO transaction. Tests prove no orphan/divergence. `CONTAINMENT.idFromName("global")` is
sole authority; Wrangler v7 is unchanged and no per-job/per-repo DO exists.

### Pre-effect spawn-owner protocol

The singleton `ContainmentDO` is the sole linearizable claim authority. KV is a
mirror/witness for provider idempotency only: it is never CAS, never a release
authority, and never a source for sequencing. Before `beginEffect` or
`beginReservedEffect`, the DO records a pre-effect owner for the full tuple
`(repo,job,event,effect,reservation_epoch,drain_owner,drain_lease_epoch,caller_nonce)`.
The unique 128-bit `caller_nonce` is generated once per logical attempt and is
reused on retries; a changed nonce is a new contender, not a retry. The live
producer, `redriveOrphanedJobs`, and `retryOrphanedSpawns` use this same protocol.

The exact DO key is
`containment:v1:spawn-owner:<repo>/<job>/<effect-id>`; the record's nonce and
full tuple must compare exactly. Its state machine is
`PREPARED -> CLAIM_ACQUIRED -> PERMIT_ISSUED -> BOUND -> DRIVING -> COMMITTED`,
with only `PREPARED|CLAIM_ACQUIRED -> ABORTED_PRE_EFFECT` allowed. A compare-owner
release/reap checks repo, job, nonce, owner, lease epoch, `permit_id=null`, and
`effect_started=false`; a mismatched owner, expired lease with uncertain permit,
or legacy record remains blocked and is never deleted. A lease-expiry reap is
permitted only after the DO proves no permit/effect and appends that proof.

The KV-facing claim boundary returns one of these typed results:

```text
acquired        = exact prepared owner atomically acquired the claim
owned           = exact same prepared owner already owns the claim, idempotently
busy            = another current owner holds the claim
legacy_unknown  = a legacy/job-only claim exists without the exact repo binding
unavailable     = claim store is unreadable or the operation is indeterminate
```

Only `acquired`/exact `owned` lets the DO issue one permit. `busy`, `legacy_unknown`, and
`unavailable` leave head unacknowledged/redrive `HELD`, issue no permit, and perform zero orphan,
release, JIT, mint, lease, start, destroy, or effect mutation. No KV boolean inference or retry spin;
once `PERMIT_ISSUED`/effect exists, reset or abandonment is illegal.

Crash seams are deterministic: claim→begin retries the nonce or blocks; permit→bind recovers the
same permit; bind→drive resumes only with it; drive→commit records its result or remains fail-closed.
Missing/ambiguous state at any seam leaves the head durable and unacknowledged.

The pre-effect ledger is versioned and repo-scoped:

```ts
{
  schema_version: 1;
  repo: string;
  job_id: string;
  event_id: string;
  effect_id: string;
  reservation_epoch: number;
  drain_owner: string;
  drain_lease_epoch: number;
  spawn_owner: string;
  caller_nonce: string;
  permit_id: string | null;
  effect_started: boolean;
  state: "PREPARED" | "CLAIM_ACQUIRED" | "PERMIT_ISSUED" | "BOUND" |
    "DRIVING" | "COMMITTED" | "ABORTED_PRE_EFFECT";
}
```

### Legacy claim/reservation quarantine

Job-only `spawn:<job>`, `done:<job>`, `orphan:<job>`, `jtenant`, `jhandle`,
`sbox`, and direct `KV.get(job)` records are legacy. A legacy claim or
reservation is classified `legacy_unknown`, copied to bounded
`containment:v1:legacy-quarantine:<sha256(raw-key)>` with
`{schema_version:1,raw_key_hash,first_seen_ms,expires_ms,source}`, and never
adopted into R14. Quarantine capacity is 256 and TTL is fixed at 24 hours;
overflow blocks closed. No unsafe delete, expiry-only effect, or job-only
release is permitted. Writers/readers remain separately tracked: `claimSpawn`
and `bindContainmentSpawnClaim` write/read the legacy forms, while
`redriveOrphanedJobs` and `retryOrphanedSpawns` read orphan records; R14's
cross-repo guarantee is narrowed to canonical R14 namespaces until this legacy
finding is separately repaired.

## Frozen behavior and invariants

1. **Claim-false liveness.** In `runContainmentDrain`, a false or typed
   `busy`/`legacy_unknown`/`unavailable` claim result is a blocked/unknown
   outcome. The event remains the head, the redrive reservation remains `HELD`,
   no permit is issued, no second claim is attempted, and the worker does not
   spin. A false claim can never be reported as successful drain/redrive.
2. **One-shot effect.** `beginReservedEffect` is issued only after the
   singleton pre-effect owner ledger records an exact `acquired`/`owned` claim.
   A stale tuple, missing permit, failed index transaction, or non-acquired
   claim has zero spawn/JIT/mint/lease/start/destroy side effects. Once
   `EFFECT_ELIGIBLE` or a started effect exists, no reset or abandonment path
   may reopen it.
3. **Ordered head.** Drain consumes strictly increasing pause sequence, one
   head at a time. A blocked head remains durable and blocks later heads; an
   event is ACKed only after its effect and completion evidence are committed.
4. **Singleton authority.** All sequence, reservation, lease, cursor, state,
   index, and completion transitions occur transactionally in the global DO.
   KV is an idempotency cache only.
5. **Webhook separation.** A normal webhook with an empty backlog follows its
   existing path and neither consults nor reserves a redrive reservation. A
   containment append is the only route that performs the reservation check.
6. **Invalid-config distinction.** Each `(switch_name, raw_value_sha256)` gets
   one durable signal/outbox id. Distinct raw values and distinct switches get
   distinct signals; retries and scheduled delivery call `bumpOnce` once per
   signal after the containment record commits.
7. **Population.** A deterministic route fixture creates 100 distinct paused
   events, contiguous sequence records, and exactly 100 successful effects.
   Every effect is uniquely bound to one canonical event; no duplicate mint,
   JIT, claim, lease, start, ACK, or effect commit occurs.
8. **Idle status.** `runnerActivityVerdict` classifies idle, offline, and HTTP
   404 as no-renew; unknown remains renewable. The previous “keepalive burns
   idle capacity” claim is REFUTED and is not reintroduced by this contract.
