## Frozen data contracts

### Canonical identity

`normalizeRedriveIdentity(repo, job_id)` is the only normalizer before any key, map, reservation,
event, claim, effect, or credential lookup. It trims only repository ASCII surrounding whitespace,
validates one GitHub `owner/name`, lowercases both for containment identity, and uses that form for
allowlists/maps; malformed or ambiguous aliases are typed fail-closed refusals.

`job_id` is canonical decimal `[1-9][0-9]*`, with `1 <= BigInt(job_id) <= 9007199254740991`.
Leading zeroes, signs, *any* surrounding/internal whitespace, fractions, exponents, negatives,
unsafe integers, and numeric round-trips are refused; no job-id trim is permitted. Only the
canonical pair enters reservation, event, effect, claim, and evidence keys.

Webhook `workflow_job.id` accepts only a safe JSON integer token in the bound above or the exact
canonical digit string; both normalize to the same string. Fractions, exponents, signs, lossy/
unsafe numbers, leading zeroes, whitespace-padded strings, null, boolean, array, or object are
400 typed refusals before a write. `installation_id` is stored/keyed as canonical decimal string,
never a number. Containment-only responses are exactly `{schema_version:1,...}` with no live fields.

The webhook reads `request.arrayBuffer()` exactly once and retains the raw UTF-8 bytes. A strict
lexical pre-parser locates the `workflow_job.id` token before any generic JSON parse; it rejects
fraction, exponent, sign, leading-zero, and whitespace-padded numeric lexemes. Only after that
pre-parser accepts the token may the implementation decode the JSON value. `request.json()` alone
is not a conforming implementation because it can erase the lexical distinction between an integer
and an exponent/fraction before the refusal is made.

For webhook identity, a nonempty trimmed `X-GitHub-Delivery` is the event id;
blank/ASCII-whitespace-only is absent. Without it, the fallback is
`sha256("containment:v1\n"+repo+"\n"+job+"\n"+action+"\n"+sha256(raw_body_bytes))`.
Delivery reuse with a different body hash is a typed 409 with no new sequence;
malformed JSON after valid HMAC is a 400 with no durable write.

### Schema/version boundary

Every durable record, API response, effect permit/binding, metric outbox, and evidence record carries
`schema_version: 1`; missing/unsupported versions are rejected before mutation, never upgraded or
interpreted, and are enumerated by focused refusal tests.

The canonical event shape remains:

```ts
{
  schema_version: 1;
  event_id: string;
  pause_seq: number;
  received_at_ms: number;
  body_sha256: string;
  raw_payload: string;
  repo: string;             // canonical owner/name
  job_id: string;           // canonical decimal
  installation_id: string;  // canonical decimal installation id
  labels: string[];
  effect_id: string;
  state: "QUEUED" | "CLAIMED" | "EFFECT_COMMITTED";
  claim: { owner: string; lease_epoch: number } | null;
  effect_permit: ContainmentEffectPermit | null;
}
```

The event id is required and canonical at every R14 boundary: intake uses the webhook delivery
id (or the exact deterministic delivery fallback above), drain uses the stored event's id, and
redrive uses that stored id when present. A redrive record with no stored event id uses the exact
derived redrive-event id below before it can enter an owner tuple; no path uses a blank sentinel.

The nested permit is not an untyped bag. Its exact schema is:

```ts
type ContainmentEffectPermit = {
  schema_version: 1;
  permit_id: string;
  repo: string;
  job_id: string;

  issued_to_epoch: number;

```

The webhook accepts a safe JSON integer token and canonicalizes it to the same decimal string as
an exact canonical digit string. An unsafe or non-integer JSON number, a noncanonical digit string,
or any lossy numeric round-trip is refused before a write; accepting a safe integer does not imply
that arbitrary numeric round-trips are accepted.

Pause, reservation, permit, binding, outbox, and metric records use the same gate. Exact derivations:
`redriveEffectId(repo,job)=containment:v1:redrive:<repo>/<job>` and
`intakeEffectId(repo,job,event)=containment:v1:intake:<sha256("containment:v1\nintake\n"+repo+"\n"+job+"\n"+event)>`; SHA-256 is lowercase hex over UTF-8 bytes and never authorizes a second effect.

### Expired HELD and reservation fencing

The exact reservation key is
`containment:v1:reservation:<canonical-repo>/<canonical-job-id>`. A `HELD`
reservation with `expires_ms > now` returns `authority-busy` and writes no
event. A `HELD` reservation with `expires_ms <= now` is reclaimed atomically in
the deciding Durable Object transaction, increments its epoch, and receives a
new transaction-generated owner/token. Equality at the boundary is expired.
Only `HELD` may be reclaimed. `EFFECT_ELIGIBLE` and `COMPLETED` never expire,
reopen, or receive a new permit. Every transition supplies and checks the full
`(repo, job_id, owner, token, epoch, path, effect_id)` tuple; a stale owner is a
typed no-op touching no KV or effect state.

### Repo-scoped containment binding

`containmentEffectJobKey(repo,job,effect)` is exactly
`containment:v1:binding:<canonical-repo>/<canonical-job>/<encodeURIComponent(effect)>` and its
record must include the canonical repo/job signature. The binding schema is:

```ts
{
  schema_version: 1;
  repo: string;
  job_id: string;

  effect_id: string;
```

Two repositories using the same numeric job id must never share a claim,
binding, completion latch, or effect. A job-only `containment:v1:job:<id>` key is
forbidden for this path. Broader legacy per-job keys are recorded separately in
the R14 ledger and are outside this repair contract.

### Bounded event index

`containedEventExists` must use a bounded, transactionally maintained index,
not a prefix scan of all event records. The index key is
`containment:v1:repo-job-index:<canonical-repo>/<canonical-job-id>` and its
schema is:

```ts
{
  schema_version: 1;
  repo: string;
  job_id: string;
  active_event_ids: string[];
  active_count: number;
  updated_at_ms: number;
}
```

`MAX_ACTIVE_INDEX_EVENTS` is fixed at **256** (at least 100). At its limit, or when the index is
missing, the transaction fails closed without scan/allocation/append/admission; no operational
backfill via `list({prefix})` is permitted. Append, claim/ack, and cleanup update the index in one
DO transaction. Tests prove no orphan/divergence. `CONTAINMENT.idFromName("global")` is sole
authority; Wrangler v7 is unchanged and no per-job/per-repo DO exists. A new canonical repo/job
pair is created only by the explicit singleton-DO `bootstrapContainedEventIndex(repo, job)`
transaction, which proves that the exact pair has no event, reservation, binding, or owner record
and writes one empty version-1 index. Bootstrap is a bounded cutover operation, never a prefix scan
or legacy backfill; after bootstrap, a missing/corrupt index blocks all normal operations until an
owner-reviewed repair restores that exact record. Fresh-pair bootstrap and post-bootstrap missing
index refusal are separate fixtures.

### Pre-effect spawn-owner protocol

The singleton `ContainmentDO` is sole linearizable authority; KV is only a typed mirror/witness and
never CAS, sequencing, release authority, or an authoritative `acquired` result. The discriminated
tuple is `OwnerTuple=(repo,job_id,path,event_id,reservation_epoch,effect_id,owner,token,drain_owner,
drain_lease_epoch,caller_nonce)`, where `path` is exactly `intake|drain|redrive`. For `intake`,
`event_id` is the required canonical webhook/DO event id and `reservation_epoch=null`; for `drain`,
`event_id` is the required canonical stored event id and `reservation_epoch=null`; for `redrive`,
`reservation_epoch` is required and `event_id` is the stored canonical event id or, only when absent,
the derived id `sha256("containment:v1\nredrive-event\n"+repo+"\n"+job+"\n"+
String(reservation_epoch))`. No empty-string/zero sentinels are valid. The live producer and both
redrive callers use the same tuple and derivation.

Canonical keys/APIs are fixed:

```text
DO active pointer key = containment:v1:spawn-active:<repo>/<job>/<path>/<encodeURIComponent(effect-id)>
DO immutable attempt key = containment:v1:spawn-attempt:<repo>/<job>/<path>/<encodeURIComponent(effect-id)>/<caller_nonce>
KV mirror key = containment:v1:spawn-mirror:<repo>/<job>/<path>/<encodeURIComponent(effect-id)>
binding key = containment:v1:binding:<repo>/<job>/<encodeURIComponent(effect-id)>
repo_job_signature = sha256("containment:v1\nbinding\n"+repo+"\n"+job)
prepare(tuple, nonce): Prepared|Busy|Unavailable
acquire(tuple, nonce): acquired|owned|busy|legacy_unknown|unavailable
confirm(tuple, nonce, permit_id): PermitIssued|Owned|Rejected|Unavailable
beginEffect(tuple, permit_id): EffectEligible|AlreadyStarted|Rejected|Unavailable
beginReservedEffect(tuple, permit_id): EffectEligible|AlreadyStarted|Rejected|Unavailable
abort(tuple, nonce, owner, token): Aborted|Rejected|Unavailable
observe(owner_key): OwnerRecord|Missing|Unknown
```

`caller_nonce` is a persisted unique 128-bit value generated once per logical attempt and reused
after crashes; unavailable preserves that nonce. DO transitions, not KV, return `acquired|owned`.
The mirror payload contains the exact `SpawnMirrorPayloadV1` fields above. The binding payload is
exactly `{schema_version:1,repo,job_id,path,event_id,effect_id,permit_id,reservation_epoch,
repo_job_signature,proof_id,issued_to_owner,issued_to_epoch}`. The exact call order is
`normalize → observe mirror/legacy → prepare → acquire → mirror write/readback → confirm →
beginEffect|beginReservedEffect → binding write/readback → bind → mark DRIVING → drive → observe /
commit → complete/ACK`; no step may skip its predecessor.

State is `PREPARED→CLAIM_ACQUIRED→PERMIT_ISSUED→BOUND→DRIVING→COMMITTED`, with only
`PREPARED|CLAIM_ACQUIRED→ABORTED_PRE_EFFECT`. `ABORTED_PRE_EFFECT` is an immutable tombstone:
the same nonce cannot reacquire; a new nonce is allowed only after DO proof of no permit, binding,
or effect. Owner/token compare-delete is allowed only for the exact repo/job/nonce/owner/token/
lease epoch and null permit/binding/effect. Only `PREPARED|CLAIM_ACQUIRED` may be reaped after
lease expiry plus that proof; uncertain/legacy state is retained and blocked.
`OwnerRecordV1=(schema_version,OwnerTuple,nonce,state,permit_id,binding_id,effect_started,
created_ms,expires_ms,tombstone)` is the exact DO value; all fields are compared canonically.

Crash rules are fail-closed: claim→begin retries the same nonce; permit→bind recovers the same
permit; BOUND→DRIVING may drive once with that permit; after DRIVING, missing immutable effect-start
proof becomes `UNKNOWN` and never calls drive again. If immutable start proof exists, reconcile or
commit with the same permit; drive→commit lost response likewise observes/reconciles that effect,
never mints a second one. `busy`, `legacy_unknown`, and `unavailable` leave the head unacknowledged
and `HELD`, with zero permit/effect/orphan/release/JIT/mint/lease/start/destroy mutations.

#### A0b owner-attempt and RPC clarification

The active pointer and immutable attempt are separate DO records. Their exact keys are the active
pointer above and `containment:v1:spawn-attempt:<repo>/<job>/<path>/<encodeURIComponent(effect-id)>/<caller_nonce>`.
The pointer contains `schema_version,repo,job_id,path,event_id,reservation_epoch,effect_id,
caller_nonce,attempt_key,state,permit_id,binding_id,effect_start_proof_id,owner,token,lease_epoch`;
the attempt contains those same fields plus `created_ms,expires_ms,tombstone`. An
`ABORTED_PRE_EFFECT` attempt is immutable and remains addressable by its caller nonce. An abort
transaction may rotate the active pointer to a new attempt only after the singleton DO proves that
the old attempt has no permit, binding, or effect-start proof; it never deletes or overwrites the
old tombstone. A missing, legacy, mismatched, or unavailable proof leaves the pointer and attempt
blocked. Compare-delete requires the exact `(repo,job_id,path,event_id,reservation_epoch,effect_id,
caller_nonce,owner,token,lease_epoch)` tuple.

negative fixtures, not completion evidence.

Ordinary generic non-R14 callers may retain the historical `claimSpawn` compatibility behavior.

use the canonical observation → DO prepare/acquire → exact mirror readback → DO confirm/permit
protocol, with no mixed legacy claim in the same attempt. A validated orphan input can seed a
candidate tuple only after canonical repo/job/schema validation; it is never ownership, evidence,
or completion and is never adopted or deleted by claim logic.

### Legacy claims versus orphan input

Job-only `spawn:<job>`, `done:<job>`, `jtenant`, `jhandle`, `sbox`, bare job-id,
and `orphan:<job>` records are not R14 authority. The orphan record is a separate
legacy read-only *input candidate* (schema/raw hash/source/first-seen/expiry), not
claim or reservation; malformed/ambiguous candidates classify `legacy_unknown` and quarantine
them under
`containment:v1:legacy-quarantine:<sha256(raw-key)>`, TTL 24h/capacity 256, and
never adopt it as ownership/evidence or delete it via claim logic. A candidate that passes canonical
repo/job/schema validation may derive a fresh R14 effect only by acquiring new DO
authority; it never reuses the legacy claim. Canonical writers are the DO
owner/reservation/event/binding APIs; `recordOrphan` remains a legacy writer,
while quarantined readers are `claimSpawn`, `bindContainmentSpawnClaim`,
`redriveOrphanedJobs`, and `retryOrphanedSpawns` until separately repaired.
Overflow/unavailable blocks.
R14's cross-repo guarantee and validation matrix cover canonical R14 namespaces
only; acceptance remains blocked for these legacy writers/readers.

## Frozen behavior and invariants

1. **Claim-false liveness.** In `runContainmentDrain`, `beginEffect`, and live
   `/webhook`, a false or typed `busy`/`legacy_unknown`/`unavailable` result is
   blocked/unknown: the head remains, redrive stays `HELD`, and zero permit,
   spawn, JIT, mint, lease, start, destroy, ACK, or effect mutations occur.
   No second claim/spin is allowed and false can never report success.
2. **One-shot effect.** `beginEffect` and `beginReservedEffect` are issued only
   after the singleton pre-effect owner ledger records an exact `acquired`/`owned`
   claim; the live `/webhook` producer uses the same sequence. A stale tuple,
   missing permit, failed index transaction, or non-acquired claim has zero
   spawn/JIT/mint/lease/start/destroy side effects. Once `EFFECT_ELIGIBLE` or a
   started effect exists, no reset or abandonment path may reopen it. After
   `DRIVING`, only an immutable `EffectStartProofV1` with the same permit may
   reconcile; no second drive is allowed without that proof.
3. **Ordered head.** Drain consumes strictly increasing pause sequence, one
   head at a time. A blocked head remains durable and blocks later heads; an
   event is ACKed only after its effect and completion evidence are committed.
4. **Singleton authority.** All sequence, reservation, lease, cursor, state,
   index, and completion transitions occur transactionally in the global DO.
   KV is an idempotency cache only.
5. **Webhook separation.** A normal webhook with an empty backlog follows its
   existing path and neither consults nor reserves a redrive reservation. A
   containment append is the only route that performs the reservation check.
6. **Invalid-config distinction.** Each `(switch_name, raw_value_sha256)` gets
   one durable signal/outbox id. Distinct raw values and distinct switches get
   distinct signals; retries and scheduled delivery call `bumpOnce` once per

7. **Population.** A deterministic route fixture creates 100 distinct paused

   Every effect is uniquely bound to one canonical event; no duplicate mint,
   JIT, claim, lease, start, ACK, or effect commit occurs.
8. **Idle status.** `runnerActivityVerdict` classifies idle, offline, and HTTP
   404 as no-renew; unknown remains renewable. The previous “keepalive burns
   idle capacity” claim is REFUTED and is not reintroduced by this contract.

## Evidence provenance and indexing

The deterministic artifact is exactly `docs/plan/evidence/T3-W17-containment-test.json`, generated
only after focused tests. Top-level keys are exactly `schema_version,artifact_id,review_input_sha,
source_seal_sha,contract_sha256,source_tree_sha256,test_tree_sha256,focused_tests,counts,sequence,
live,exclusions`; `live:false`. `source_seal_sha` is the sole name for the implementation commit
and no evidence field emits `source_commit_sha`. The exact nested shapes are:

`sequence` is the embedded append-only history; there is no sidecar index, external append, or
separate mutable sequence file. Canonical JSON is UTF-8, no BOM, LF only, no final newline,
recursively UTF-8-byte-lexicographic object keys, preserved array order, RFC-8259 escaping, finite
integers, and separators `,`/`:` only. SHA-256 is lowercase hex over exact bytes. The manifest is
sorted `/`-normalized allowlisted paths, each `<path>\0<sha256(file_bytes)>\n`; source/test/contract
bytes retain their original line endings. Exclude `.git`, node_modules, coverage/logs/generated
outputs, prior outputs, the artifact itself, and no sidecar from their own manifest/digest.

The exact two-pass sequence rule is: (1) freeze external `review_input_sha`, collect bytes and the
sorted manifest, hash source/test/contract trees, run tests and freeze byte-preserved outputs, then
build the artifact with the newest sequence entry's `current_digest=null`; (2) canonicalize those
artifact bytes, calculate `current_digest` over those bytes, insert that digest into that newest
entry, and write the final artifact once. The digest is never recalculated over the inserted value;
there is no self-hash. Prior sequence entries are byte/field-preserved, and their
`previous_digest`/`current_digest` values are never rewritten. Missing/partial/self-referential
provenance, extra files, or a seal equal to the review input when it is not the implementation
commit is RED. Phase-B owns plan-integrity completion.
